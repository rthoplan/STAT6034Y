1. Validation vs. Testing: The ML Workflow

A common trap in machine learning is confusing the Validation set with the Test set. While both are used to evaluate a model, they serve completely different purposes in the model's lifecycle. Think of it as the difference between a practice exam and the final exam.

Validation Set

  • Purpose: Tune hyperparameters and select the best model complexity.
  • Frequency: Used iteratively (many times) during development.
  • Risk: "Indirect leakage." The model doesn't train directly on this data, but because you make decisions based on its results, the model can still overfit to it over time.

Test Set

  • Purpose: Provide an unbiased, honest estimate of final, real-world performance.
  • Frequency: Used strictly ONCE at the very end of the project.
  • Risk: If you use the test score to go back and change your model, it becomes a validation set, and your final estimate is ruined!

The Accuracy Trap

If a dataset is highly imbalanced, Accuracy is a terrible metric.

Scenario: 90% of customers naturally stay. You build a "dumb" baseline model that simply predicts "Everyone will stay".

Baseline Accuracy 90%
Churners Found (Sensitivity) 0%

The model looks great on paper (90%), but is completely useless for the business problem. This is why a simple baseline is required for comparison.
